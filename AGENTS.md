# Инструкции для AI-агента: VPN-платформа

## Обязательное чтение до любых изменений

1. `docs/vpn-application-implementation-tz.md` — стек, структура, правила и запреты.
2. `docs/vpn-service-tz.md` — пользовательские сценарии и бизнес-требования.
3. `docs/vpn-technical-spec.md` — инфраструктура, ноды и эксплуатация.
4. `docs/vpn-project-journal.md` — решения, риски и история изменений.

Если эти документы лежат в корне репозитория, сначала перенеси их в `docs/` без изменения содержания и затем обнови ссылки в этом файле.

## Контекст продукта

Платформа включает Telegram-бота, кабинет пользователя, админку, API, worker и управление VPN-нодами. Пользователь платит через кабинет, добавляет свой device-specific subscription URL в Happ и получает доступ до окончания подписки. Стартовый тариф — 200 ₽, до трёх устройств; тарифы и лимиты управляются из админки.

## Рабочий порядок

1. Сначала изучи документы и кратко перечисли, что понял.
2. Выполняй только один согласованный этап за раз.
3. Перед изменением схемы БД создай миграцию.
4. Перед изменением API обнови контракты, OpenAPI и тесты.
5. После изменения решения или требования добавь запись в `docs/vpn-project-journal.md`.
6. Запускай проверки, указанные в ТЗ, и сообщай их результат.

## Стартовый этап

Сначала создать только каркас монорепозитория:

- pnpm workspaces;
- приложения `web`, `api`, `bot`, `worker`;
- общие `packages/contracts` и `packages/config`;
- Docker Compose для локальных PostgreSQL и Redis;
- TypeScript strict, ESLint, Prettier, базовый CI;
- health endpoint в API;
- README с локальным запуском.

На этом этапе не подключать оплату, Telegram production webhook, Xray/VLESS, реальные VPN-ноды, эквайринг, секреты и боевой деплой.

## Жёсткие запреты

- Не хардкодить секреты, токены, тарифы, device limits, домены и ID нод.
- Не выдавать доступ по return URL, скриншоту или клиентскому флагу.
- Не хранить данные карт, полные subscription URL или секреты в логах.
- Не давать frontend-у доступ к БД, Redis, платёжному провайдеру или node agent.
- Не добавлять микросервисы, Kubernetes, GraphQL, мобильные приложения и «временные заглушки безопасности» без отдельного решения в журнале.
- Не редактировать конфигурации боевых нод вручную.

## Definition of Done

Задача готова, только если есть валидация, проверки доступа, тесты основного и ошибочного сценария, необходимые миграции, безопасные логи, обновлённая документация и успешно пройденные проверки.
